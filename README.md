# ML Assignment 2: Bank Term-Deposit Subscription Classifier

## a. Problem Statement

Portuguese bank telemarketing campaigns call existing clients to sell term
deposits, but only a small fraction of calls convert. The goal of this project
is to predict whether a client will subscribe to a term deposit (`y = yes/no`)
using demographic, financial, and campaign attributes. Five classifiers are trained on the
same stratified split and compared with six metrics, and an interactive
Streamlit app evaluates any of the saved models on an uploaded, labeled test
CSV.

## b. Dataset Description

- **Name:** Bank Marketing (`bank-full.csv`)
- **Source:** [UCI Machine Learning Repository: Bank Marketing](https://archive.ics.uci.edu/dataset/222/bank+marketing)
- **Size:** 45,211 instances (≥ 500 required ✔)
- **Features:** 16 input attributes (≥ 12 required ✔): client data (`age`,
  `job`, `marital`, `education`, `default`, `balance`, `housing`, `loan`),
  contact data (`contact`, `day`, `month`), and campaign data (`duration`,
  `campaign`, `pdays`, `previous`, `poutcome`)
- **Target:** `y`: did the client subscribe to a term deposit? (binary:
  `yes` / `no`)
- **Class balance:** highly imbalanced, about 88.3% `no` vs 11.7% `yes`,
  which is why metrics beyond accuracy (AUC, F1, MCC) matter here.
- **Leakage handling:** the `duration` column is **excluded** from training.
  Call duration is only known *after* a call finishes, so using it would leak
  information unavailable at prediction time (as the UCI documentation itself
  warns). That leaves 15 predictors. Other campaign attributes must also be
  checked for availability at the intended prediction time; this experiment
  does not establish that every feature is available before a call.

The raw CSV is semicolon-delimited; download it from UCI and place it at
`data/bank-full.csv` (it is intentionally not committed to the repository).

## d. Models Used and Comparison

All five classifiers share the same preprocessing (median imputation +
standardization for numeric columns; most-frequent imputation + one-hot
encoding for categoricals) inside a single scikit-learn `Pipeline`, trained on
the same stratified 80/20 split (`random_state=42`): 36,168 training rows
and 9,043 held-out test rows. The test set contains 7,985 `no` and 1,058 `yes`
labels and is saved as `test_data.csv`. Precision, recall and F1 use `yes` as
the positive class. AUC uses predicted probabilities, or decision scores for
the SVM. The test set is also used to choose the reported winner, so these
results are not an independent estimate of the selected model's performance.

## How to run locally

Use **Python 3.12** and the pinned dependencies below. The committed joblib
pipelines were trained with scikit-learn 1.5.1, NumPy 1.26.4, SciPy 1.13.1,
and joblib 1.4.2. Loading them with different library versions is unsupported
and can fail before predictions run. Do not upgrade deployment dependencies
independently of retraining and validating all five artifacts.

```bash
python -m pip install -r requirements.txt
python explore_data.py        # optional dataset sanity check
pytest                        # unit tests
python train_models.py        # trains 5 models, writes model/, results/, test_data.csv
streamlit run app.py          # launch the evaluation app
```

## Streamlit Community Cloud deployment

Deploy this repository's `main` branch with `app.py` as the entrypoint. In
**Advanced settings**, explicitly select **Python 3.12** before deploying;
the default Python version may not support the pinned training dependencies.

If an existing deployment uses Python 3.14, rebooting or editing requirements
does not change its Python version. Record its subdomain and settings, then
delete and redeploy the app with Python 3.12, reusing the subdomain. See the
[official Python-version instructions](https://docs.streamlit.io/deploy/streamlit-community-cloud/manage-your-app/upgrade-python).
After deployment, upload `test_data.csv` and check all five dropdown options,
not just the initial page: model loading only happens after a CSV is uploaded.

## Streamlit app features

- **Download** the provided labeled holdout and upload a test CSV with all
  15 model inputs and the `y` target. CSV files must be UTF-8 encoded,
  comma- or semicolon-delimited, no larger than 10 MB and at most 100,000 rows.
  The target must contain both `no` and `yes` to compute AUC.
- **Select** any of the five saved models from a dropdown (loaded from
  `model/`, never retrained)
- **View** all six evaluation metrics: Accuracy, AUC, Precision, Recall, F1, MCC
- **Inspect** the labeled confusion matrix and full classification report
  together below the metrics, with a collapsible preview of the uploaded data.
  Model selection and CSV upload are available above the results.
  The matrix uses `yes` as positive: rows are actual labels, columns are
  predicted labels, and its cells show TP, FN, FP and TN.
- **Validate** required columns, duplicate headers, labels and numeric values.
  Missing feature values are handled by the fitted imputers. Extra columns,
  including `duration`, are ignored and listed in the app.
